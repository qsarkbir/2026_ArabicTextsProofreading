# OpenITI 校正アプリ

OpenITI のテキストを、元になった刊本のページ画像と並べて校正するローカルアプリです。ページ画像は Internet Archive（IIIF）から表示するか、手元の PDF をアップロードして使います。Anthropic（Claude）またはOpenAIにページ画像を読み取らせて、テキストとの食い違いを示すこともできます。

## 起動

Python 3.10 以上で動きます。手作業の校正とOpenAI OCRは標準ライブラリで動きます。Claude OCRにはanthropicパッケージが必要です。

```bash
python -m proofreader
```

Windows では `start.bat` をダブルクリックしても起動できます（`.venv` があればそれを使います）。ブラウザで http://127.0.0.1:8765/ が開きます。`--port` でポートを、`--no-browser` でブラウザを開かない設定にできます。アプリの画面（タブ）をすべて閉じて約30秒たつと、サーバーは自動的に終了します（通信が途絶えた場合は3分後）。ホーム画面の「アプリを終了」ボタンでも終了できます。自動終了を止めるには `--keep-running` を付けます。作業データは `projects/` に保存されます（環境変数 `PROOF_DATA` で変更可）。

### ブラウザだけで使う（静的版）

サーバーを使わず、静的ファイルとして配信しても校正できます。データはブラウザの IndexedDB に保存されます。

```bash
python -m http.server -d proofreader/static 8780   # http://127.0.0.1:8780/
```

OpenITI の URI かテキストファイルからの作成、校正（本文・確認済み・注記）、保存履歴、検索、OpenITI テキスト・注記 CSV・TEI XML の書き出しができます。手元の PDF をページ画像として使うこともできます（「資料・ページ対応」からアップロードして対応を合わせます。ホームの「OpenITIにないテキストをPDFから作成する」も使えます）。PDF はこのブラウザの中に保存されるので、容量に注意してください（足りないときは何も変更せずにお知らせします）。Internet Archive の検索・資料の選択・ページ画像の表示と対応付けもブラウザから直接できます（検索語と画像の取得先が Internet Archive に伝わります。画像サーバーが混み合って応答しないときは数回やり直し、それでもだめなら案内を表示します）。IA の PDF はブラウザから取得できないため、「資料・ページ対応」に出るリンクからダウンロードして、そのファイルを選ぶと、このブラウザに保存して画像の代わりに使います。AI 読み取り・ZIP・差分・PDF のサーバー側の保存は、これまでどおり `python -m proofreader` で使います。

**バックアップ**：ブラウザのデータはサイトのデータを消したり容量が足りなくなったりすると失われます。プロジェクトの「書き出し」メニュー、またはホームの「バックアップを書き出す」で `<名前>.proofreader.json` を保存してください（ホームに最後のバックアップの日時と、ブラウザの使用量が出ます）。ホームの「バックアップから読み込む」で、新しいプロジェクトとして戻せます。同じファイルをローカル版（`python -m proofreader`）でも書き出し・読み込みでき、どちらの版で始めた作業も引き継げます。PDF と AI の読み取り結果はバックアップに含まれないので、読み込んだ後に PDF を選び直してください（静的版では校正画面の画像の欄にファイル選択が出ます）。

**GitHub Pages で公開する**：リポジトリの Settings → Pages → Source を「GitHub Actions」にします。以後、テストが成功した `main` への push のたびに `proofreader/static/` が配信されます（`.github/workflows/tests.yml` の `deploy` ジョブ。リポジトリが private の場合、Pages の利用には有料プランが必要で、公開されるサイトは誰でも見られます）。配信されるのはアプリだけで、OpenITI のテキストは利用者のブラウザが GitHub から取得します。

### Claude OCR を使う場合

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

API キーは、リポジトリのルート（`README.md` と同じ場所）に `.env` ファイルを作って書いておきます。

```
ANTHROPIC_API_KEY=sk-ant-...
```

Claude OCR を使うときは、パッケージを入れた仮想環境の Python でアプリを起動します。システムの Python で `python -m proofreader` と実行しても、anthropic が無く `.venv` がある場合は自動的に `.venv` の Python で起動し直します（`PROOFREADER_NO_REEXEC=1` で無効）。

```bash
.venv\Scripts\python -m proofreader
```

`.env` は起動時に読み込まれ、PC 全体に設定した環境変数より優先されます。`.gitignore` で除外してあるので、コミットされることはありません。`.env` を使わずに、環境変数 `ANTHROPIC_API_KEY` を設定するか `ant auth login` でログインしておいてもかまいません。

読み取りは校正者がページを開いて「AIで読み取る」を押したときだけ行い、結果は `projects/<テキスト>/ocr/` に保存して再利用します。モデル入力欄の候補から Opus 5.5（既定）・Sonnet 5.5・Haiku 5.5 を選べ、選んだモデルは次回も使われます。安いモデルほど読み誤りが増えることがあるので、気になるページは「読み直す」で別のモデルを試してください。選べるモデルは `proofreader/ocr.py` の `MODELS` で変えられます。

### OpenAI OCRを使う場合

`.env.example` を参考に、ルートの `.env` に次を設定して再起動します。

```dotenv
OPENAI_API_KEY=ご自身のAPIキー
OPENAI_OCR_MODEL=ご自身のアカウントで利用できる画像対応モデルID
```

校正画面で提供元を「OpenAI」にし、画像入力対応のモデルIDを入力します。Responses APIを使い、画像・読み取り指示を送信します。追加SDKは不要です。キーはサーバー側だけで使い、本文・書誌の出力には含めません。料金は提供元・モデル・画像によって異なります。自動的な他社への切替や全冊一括読み取りは行いません。

「保存した読み」で以前の結果を選べます。「読み直す」は新しい結果を追加し、古い読みは `ocr/history/<ページ番号>/` に残します。同じ画像に対応する結果だけを比較に使います。ページの対応を変えてから読み直すと、その新しい画像の結果として保存します。

### OpenITIにないテキストを作成する場合

ホームの「OpenITIにないテキストをPDFから作成する」を開き、書名・著者・底本・出典・利用条件を入力してPDFを選びます。表紙などを除いた最初と最後の本文画像、巻、最初の印刷ページ番号を指定してください。選択範囲に連番を付けた空の本文を作り、手入力または1ページずつのAI読み取りで校正を進めます。飛び番・欠頁はこの初期作成フローでは自動判定しません。

新規プロジェクトは `local-...` の仮IDで保存します。OpenITIに登録済みであることを意味しません。上部の「書誌」で入力内容を変更できます。正式な提出前に、既存の著者・作品レコード、提出用URI、版のYAML、本文と権利条件を確認してください。

## 流れ

1. **テキストを読み込む**：OpenITI のバージョン URI（例：`1014IbnMaryamTilimsani.Bustan.Kraken22021817402301-ara1`）か GitHub の URL を入力します。手元の OpenITI 形式ファイルも使えます。ページ区切り（`PageV..P..`）のあるテキストが対象です。
2. **ページ画像を選ぶ**：メタデータ（yml）に Internet Archive へのリンクがあれば候補に出ます。なければ Internet Archive を検索するか、識別子を直接入れるか、PDF をアップロードします。
3. **ページの対応を合わせる**：テキストのページと同じ画像が出るまで番号を動かします。途中でずれたら、校正画面の ◀ ▶ でそのページ以降だけ直せます。
4. **校正**：左に画像、右にそのページのテキストが出ます。入力欄の内容が確定テキストで、自動で保存されます。AIの読み取り結果がある場合は、食い違う語が黄色で示され、点線の枠をクリックするとその読みに置き換わります。

Internet Archive のページ画像は、アプリのサーバー経由で取得し、`projects/<slug>/cache/scan/` に保存して再利用します。1冊で数十〜数百 MB になることがあります。キャッシュは削除しても安全で、必要になったときに取り直します。IIIF が応答しない場合は、archive.org の BookReader の画像 URL で取り直します。

Internet Archive の資料は、「資料・ページ対応」の「作業フォルダーのPDF」から PDF を保存することもできます（任意・上限 500 MB）。保存先は `projects/<テキスト>/files/` です。PDF はページ数がページ画像の枚数と一致するときだけ使い、一致しない場合は削除して理由を表示します。保存すると、ページ画像と AI の読み取りに PDF を使うため、archive.org に接続しなくても表示できます。「オンラインの画像に戻す」で元の画像に戻せます（PDF は残ります）。

## プロジェクトの削除

ホームの一覧で、プロジェクトの「削除」を押します。修正したテキスト・メモ・保存履歴・AIの読み取り結果・保存したPDFやページ画像（ブラウザ版では最後のバックアップの日時も）がすべて削除され、**元に戻せません**。削除する前に、画面の「バックアップを書き出す」で保存しておくことをお勧めします。確認の欄に「削除」と入力すると削除できます。

## 書き出し

書き出す前に最新の編集を保存します。保存に失敗した場合は、校正画面の「保存を再試行」を押してください。未保存の変更は画面に保持されますが、ブラウザの強制終了後には復元できません。

- **校正済みテキスト**：OpenITI 形式のまま。修正していないページは元のファイルと1文字も変わりません。
- **差分（.diff）**：元テキストとの unified diff。
- **注記・確認状況（CSV）**
- **TEI XML（基本構造）**：書誌、章節、段落、巻頁、韻文の半句区切り、ページ注記を出力します。IA画像の参照も含めます。OpenITIのページ末尾マーカーを、TEIのページ先頭の `pb` に変換します。未対応タグは本文に残し、`encodingDesc` に警告を記録します。異本の校異装置・語単位の校訂判断・OpenITI固有TEIプロファイルの完全な変換は対象外です。
- **本文・書誌パッケージ（ZIP）**：mARkdown本文、版YAMLの下書き、書誌JSON、提出前の確認事項を含めます。著者・作品YAMLや正式URIを自動発行するものではありません。PDFやAPIキーは含みません。

## 比較の設定

「比較の設定」で、ハムザやター・マルブータの違い、句読点、語の続け書き・分かち書きの違いを無視するかどうかを切り替えられます。母音記号を厳密に比較する設定もあります。OCR結果の柱（ページ番号）と脚注は、既定では比較から外しています。構造記号や改行をまたぐ置換は無効になり、原本を見た手動の修正が必要です。途中で打ち切られたOCRによる置換・削除も無効です。

## 校正を続けるための操作

- **取り消す・やり直す**：手入力とOCR提案の採用を取り消せます。本文内では Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z も使えます。履歴は同じページを開いている間のみ保持します。
- **保存履歴**：保存前の本文を `work.json` に残し、ページを移動・再起動しても復元できます。自動保存は頻繁に行われるため、5分以内の保存は1件にまとめ、その編集を始める前の本文を残します（続けて編集しても5分ごとに1件）。1ページあたり新しい100件まで保持します。復元すると、復元直前の本文も必ず履歴に残ります。未保存の入力の復旧機能ではありません。復元は本文だけを戻し、注記・確認状況は戻しません。
- **複数タブ**：同じページの古い版から保存すると競合として止めます。未保存の本文をコピーしてから再読み込みし、最新本文と照合してください。更新後は古いタブも再読み込みが必要です。
- **確認済み**：本文を変更すると確認済みを解除します。修正内容を確認してから再度チェックしてください。
- **未割当の末尾**：最後のページ記号より後に本文がある場合、独立した未割当部分として編集・検索できます。ページ画像は自動で割り当てません。
- **ページを探す**：校正後の本文・注記を検索し、未確認・修正あり・注記ありで絞り込めます。
- **記号の挿入**：入力欄の上の「記号：」ボタンで、OpenITI の記号（`# `、`~~`、`%~%`、`### |` など）をカーソル位置または選んだ行に挿入します。行頭の記号は選んだすべての行に付きます。「取り消す」で戻せます。ページの区切り（`PageV..P..`）と `ms...` は、ページの分割に影響するためボタンにはありません。
- **画面の分け方**：幅が広い画面では、入力欄と比較欄がそれぞれ独立してスクロールします。入力欄の右下の角をドラッグすると高さを変えられ、次回も同じ高さになります。幅が 900px 以下の画面では、ページ全体がスクロールします。
- **資料・ページ対応**：上部のリンクから開きます。開いていたページを基準に対応を確かめられます。対応のプレビューは保存されず、変更して確定した場合だけ全体に適用し、途中ページの補正を解除します。資料を選び直しても確定するまでは現在の資料のままで、確定したときに新しい資料へ切り替えて対応を初期化します。「キャンセル」で何も変えずに元のページへ戻ります。

更新時の注意と変更履歴は [リリースノート](RELEASE_NOTES.md) を参照してください。

## 開発時の確認

```bash
python -m unittest discover -s tests -v
node --test tests/*.test.js
node --check proofreader/static/app.js
node --check proofreader/static/workflows.js
node --check proofreader/static/compare.js
node --check proofreader/static/local/openiti.js
node --check proofreader/static/local/work.js
# local/ の他のファイル（bundle.js・tei.js・store.js・router.js）も同様
```

ブラウザ確認用に `python -m tests.preview_server` を実行すると、合成データだけを使うサーバーが `http://127.0.0.1:8772/` で起動します（Internet Archive 形式の `ui-fixture` と PDF の `pdf-fixture`）。最初の保存だけ意図的に失敗するため、再試行を確認できます。既存の `projects/` と有料OCRは使用しません。Ctrl+C で終了すると検証データも削除します。

ブラウザ自動テストは `pip install playwright` と `python -m playwright install chromium` の後に `python -m tests.browser_smoke` で実行できます。既存Chromiumは自動検出し、`CHROMIUM_PATH` でも指定できます。合成データと模擬AIだけを使い、課金しません。TEIスキーマ検証は `lxml` と公式 `tei_all.rng` を用意し、`python -m tests.validate_tei /path/to/tei_all.rng` で実行します。GitHub Actionsにも設定しています。

変更は作業用ブランチから PR を作って `main` にマージします（`main` への直接 push はできません）。

静的ブラウザ版（GitHub Pages などでの配信）の設計と決定事項は [docs/static-design.md](docs/static-design.md) にあります。

PDF表示にはApache-2.0のPDF.js 6.5.438を同梱し、JavaScriptのevalを無効にしています。CDNへの接続は不要です。ただし、特殊なフォント・CMap・WASM補助資源を必要とするPDFは追加対応が必要な場合があります。WebフォントとAI・IA・OpenITIからの取得はネットワークを使用します。
